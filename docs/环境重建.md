# 从零重建 VoiceLab 环境

目标：在一台干净机器（Windows / Linux，NVIDIA GPU）上，把本仓库变成可运行的 VoiceLab。
所有产物都落在项目目录内，不需要管理员权限，也不写用户主目录。

---

## 0. 前置条件

| 需要 | 说明 |
|---|---|
| Python 3.12 | 或 [uv](https://docs.astral.sh/uv/)（推荐，`uv` 会自己下载 Python） |
| Git | 拉上游仓库 |
| ffmpeg | 视频抽音频 / 格式转换（`video2audio.py`、UVR5 需要） |
| NVIDIA GPU + 驱动 | 推理实测 8 GB 显存可跑（RTX 5060 Laptop）；纯 CPU 也能跑但慢一个量级 |

---

## 1. 克隆并建三个虚拟环境

```bash
git clone <本仓库> VoiceLab && cd VoiceLab

# 推理 + 训练
uv venv .venv-tts --python 3.12
uv pip install -p .venv-tts \
    --extra-index-url https://download.pytorch.org/whl/cu128 \
    --index-strategy unsafe-best-match \
    -r requirements/tts.txt

# ASR 标注（同样锁了 +cu128 版 torch，需要相同参数）
uv venv .venv-asr --python 3.12
uv pip install -p .venv-asr \
    --extra-index-url https://download.pytorch.org/whl/cu128 \
    --index-strategy unsafe-best-match \
    -r requirements/asr.txt

# UVR5 人声分离（CPU 版 torch 足够，纯 PyPI，无特殊参数）
uv venv .venv-uvr --python 3.12
uv pip install -p .venv-uvr -r requirements/uvr.txt
```

> **为什么必须带那两个参数**（实测踩坑，2026-11）：`torch==2.11.0+cu128` 只存在于
> PyTorch 官方 CUDA 索引，而 `certifi` 这类包两个索引都有但版本不同步。
> uv 默认对每个包**只认第一个命中它的索引**（防依赖混淆攻击），解析必然失败。
> `unsafe-best-match` 让 uv 跨索引取版本——本项目两个索引都是官方源，可放心用。
> **pip 用户不受影响**：`pip install --extra-index-url ...` 本来就跨索引取版本。
>
> **不要并发跑多个 `uv pip install`**：uv 全局缓存的 wheel 锁会让后起的安装超时报
> `Failed to acquire lock on the client cache`。串行安装，或设 `UV_LOCK_TIMEOUT`。
> 若被中断过的安装反复卡锁，加 `--no-cache` 是可靠出路（代价：重复下载，慢约 2~3 倍）。

Linux 下解释器路径是 `.venv-tts/bin/python`（下文 `.venv-tts/Scripts/python.exe` 自行替换）。

> 不想用 uv：`python -m venv .venv-tts` + `pip install -r requirements/tts.txt` 亦可，
> 只是 `torch==2.11.0+cu128` 仍需 `--extra-index-url`。

## 2. 上游推理与训练代码（vendored 目录）

```bash
mkdir -p _src
git clone https://github.com/RVC-Boss/GPT-SoVITS.git _src/GPT-SoVITS-main
```

仓库自带的 `config.json` 里 `pretrained_root` 指向 `_src/GPT-SoVITS-main/GPT_SoVITS/pretrained_models`，
下一步会把权重拉到那里。

## 3. 下载模型权重

```bash
# GPT-SoVITS 推理所需：BERT、CNHuBERT、BigVGAN、s1v3/s2Gv3 基座、G2PW 多音字
.venv-tts/Scripts/python.exe tools/fetch_models.py

# Qwen3-ASR（自动标注的耳朵）
.venv-asr/Scripts/python.exe tools/fetch_qwen_asr.py
```

`fetch_models.py` 覆盖**全部**推理权重，一台干净机器跑完它就不需要任何手工复制：
目录型三个（BERT/CNHuBERT/BigVGAN，ModelScope 优先、hf-mirror 兜底）
+ 单文件基座 `s1v3.ckpt`/`s2Gv3.pth`（上游 git 仓库不含权重，从官方权重仓 `lj1995/GPT-SoVITS` 拉）
+ `fast_langdetect/lid.176.bin`（125 MB，官方 fastText 模型，带 MD5 校验；
  缺了它在**模型加载阶段**就 FileNotFoundError，fresh 部署实测踩过）
+ `G2PWModel.zip`（从 `XXXXRT/GPT-SoVITS-Pretrained` 下载、解压到两处加载路径后自动删 zip）。
用 `--check` 可只体检不下载。中断重跑即可：所有下载都是**按体积/MD5 验完才判完成**的断点续传，
不会把半截文件当成就绪。

UVR5 权重首次调用 `tools/uvr5.py separate` 时自动下载到 `uvr5/weights/`。
网络受限时手工放 4 个 onnx + 3 个元数据 JSON（清单见 README「UVR5」一节）。

## 4. nltk 数据（英文前端）

已随仓库放在 `runtime/nltk_data/`（`corpora/cmudict.zip` + `taggers/averaged_perceptron_tagger_eng.zip`）。
缺失时补：

```bash
.venv-tts/Scripts/python.exe -c "import nltk; nltk.download(['cmudict','averaged_perceptron_tagger_eng'], download_dir='runtime/nltk_data')"
```

`tools/runtime_paths.py` 会把 `NLTK_DATA` 指向项目内，找不到时才回退用户主目录的旧数据。

## 6. 验证

```bash
# ① 列出音色（应看到 zeroshot 等）
.venv-tts/Scripts/python.exe tools/voicelab.py list

# ② 零样本合成（用自己的参考音频 + 逐字文本）
.venv-tts/Scripts/python.exe tools/voicelab.py speak \
  -p zeroshot -r data/refs/default.wav -R data/refs/default.txt \
  --ref-lang 日文 -t "这是一个部署验证。" -l 中文 -o out/_smoke.wav

# ③ ASR 回环：可懂度必须 ≥ 0.85
.venv-asr/Scripts/python.exe tools/asr_check.py out/_smoke.wav "这是一个部署验证。"

# ④ 守卫回归测试（9 项全 PASS）
.venv-tts/Scripts/python.exe tools/test_guard.py
```

⚠️ **不要只凭"命令没报错"判定成功。** 本项目吃过教训：上游返回 int16，
若归一化缺失，`soundfile` 会把削顶噪音当正常音频写出——听感刺耳、数值上
`mean|abs|` 从正常的 ≈0.04 变成 ≈0.89。②③ 两步就是为了卡这个问题，
`test_guard.py` 的 `saturated_audio` 规则是兜底。

## 7. 换机器 / 搬家

配置里的路径全部**相对项目根**，所以：

- 直接整个目录 `D:\VoiceLab` → `E:\work\voicelab`，不用改任何配置；
- 但三个 `.venv-*` 与 `train/libs` 绑定解释器绝对路径，**换机器要重建**（第 1 步，`requirements/` 已精确锁版本）；
- `models/`、`data/`、`_src/` 里的权重大，不在 git 里，需重新下载或用 `fetch_*.py`。
